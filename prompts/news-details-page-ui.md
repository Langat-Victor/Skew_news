# Prompt: SKEW news News Details Page UI

## Goal

Build the SKEW news news details page from the attached UI reference as a real, responsive Next.js route at `/news/[slug]`, reusing the Design System v1.0 tokens and the primitives already in the repo.

The reference is a full-page composition: the existing dark utility bar and white site header, then a **two-column content area** on the surface background, then a full-width newsletter band, then the existing dark footer.

- **Left column (main article)** — kicker, headline, byline + Save/Share/More actions, hero image with caption and credit, a bordered `Bias Distribution` card, the article body, then a `Related Stories` grid of 6 items.
- **Right column (analysis sidebar)** — three bordered panels: `Bias Analysis`, `AI Summary`, `Source Breakdown`.
- **Below both columns** — a full-width `Stay Informed. Stay Balanced.` newsletter band.

This is a **presentational** task. No Supabase, no Clerk, no scraping, no AI, no route handlers. The page renders typed local mock modules.

## Decisions and assumptions

Confirmed with the user:

1. **All 12 stories are routable.** Every home card links to `/news/<id>`. The Trump/Iran article (`trump-iran-peace-proposal`) is transcribed verbatim from the reference; the other 11 get short authored mock detail records (decision 10). `generateStaticParams` returns all 12 slugs; any other slug calls `notFound()`.
2. **The topic rail is hidden on the details page.** `<TopicRail />` moves from `app/(site)/layout.tsx` into `app/(site)/page.tsx`, which returns `<><TopicRail /><main>…</main></>`. The rail is a home-page affordance, not site chrome; the reference goes header → article with no chip band. `(site)/layout.tsx` keeps utility bar, header, and footer.

Assumptions made without asking:

3. **`Home` is only active on `/`.** With a second route in the group, `NAV_ITEMS`' hardcoded `active: true` would underline `Home` while reading an article. Extract the nav list into `components/layout/site-nav.tsx` (`"use client"`, `usePathname()`), with `active = pathname === item.href`. `SiteHeader` stays a Server Component; the client boundary is the nav list only. Markup, classes, and inert-`<span>` behaviour are carried over byte-for-byte.
4. **Reference-faithful UI plus the four analysis fields AGENTS.md §19 requires.** The reference shows summary, framing percentages, and the disclaimer, but **not** sentiment, confidence, framing notes, or loaded terms — all of which §19 requires the details page to display. Resolution: the three reference panels are built exactly as drawn, and the missing required fields go in **one additional sidebar panel, `Framing Details`**, below `Source Breakdown`, built from the same panel shell. This is the smallest change that satisfies both the reference and §19. It is the one element on the page not in the mockup — flag it in the completion summary so it can be dropped in one file if unwanted.
   - Related §19 gap, **explicitly out of scope**: article *cards* are also required to show the sentiment label and confidence, and the shipped `NewsCard` shows neither. That is a home-page change, not a details-page change; note it, do not fix it here.
5. **`BiasMeter` gains one optional prop, not a rewrite.** The reference's `Bias Distribution` bar is the existing `full` variant (32px tall, spelled-out labels) but with `12 sources` beneath it instead of the `0% / 50% / 100%` axis. Add `axis?: boolean` defaulting to **`true`**, so `/design-system` output is byte-identical. `axis` is only meaningful when `variant="full"`. Do not touch sizes, colors, label strings, the sum-100 warning, or the zero-segment filter.
6. **The gradient placeholder is extracted, not triplicated.** The hero image, the 6 related thumbnails, and the existing home card all need the same "no scraped image yet" art. Move that branch into `components/ui/placeholder-art.tsx` (`category`, `iconSize`, `className`) and have `NewsCard` compose it. This is a task-caused extraction, not an unrelated refactor: the alternative is the same inline gradient block in three files. `NewsCard`'s rendered output must not change.
7. **Nothing new becomes focusable.** Following the shipped precedent, controls with no backing feature render as **visually correct inert markup**, never as focusable no-op controls or `href="#"`: `Save`, `Share`, the `…` overflow, all four panel info icons, `How We Analyze Bias`, `Provide Feedback`, `View All Sources`, and the newsletter field + `Subscribe`. In particular the newsletter email field is a **styled `<div>`, not an `<input>`** — a real input the reader can type into that discards the address is worse than an obvious placeholder. Each carries a `TODO` naming the feature that will activate it. The genuinely working links are the story links (`/news/<id>`) and `Home`.
8. **Story ids become a literal union so detail coverage is compile-checked.** Change `TOP_NEWS` to `... ] as const satisfies readonly TopNewsStory[]` and export `type StoryId = (typeof TOP_NEWS)[number]["id"]`. Then `ARTICLE_DETAILS: Record<StoryId, ArticleDetail>` fails to typecheck if any of the 12 stories lacks a detail record. Story values are unchanged; `readonly` properties remain assignable to `TopNewsStory`/`BiasBreakdown`.
9. **The reference's source counts are reproduced by rounding, not by hand.** The panel shows `Left 2 (20%)`, `Center 4 (31%)`, `Right 6 (49%)` of `12 Total Sources`. Those percentages are the analysis framing percentages, not count proportions (2/12 = 16.7%). Deriving counts from `12 × 20/31/49` with **largest-remainder rounding** gives floors `2 / 3 / 5` = 10, remainders `.4 / .72 / .88`, so the two spare sources go to right and center → **2 / 4 / 6**, exactly as drawn. So `sourceCounts` is always computed by `sourceCountsFor(sourceCount, bias)`; no story hardcodes it, and counts always sum to `sourceCount`.
10. **The 11 non-reference articles get short, deliberately conservative mock copy.** Each gets exactly **3 body paragraphs and 3 summary bullets** in neutral wire-service tone restating its existing headline, plus authored `framingNotes` (one sentence) and 2–4 `loadedTerms`. Hard rules for that copy: **no quotes attributed to any person, named or anonymous; no invented statistics, dates, or institutional claims beyond the headline; no photo caption or credit.** The reference article's quotes and photo credit are transcribed from the user's own mockup and are the only ones on the site. Byline for all 11 is `SKEW Staff`, which is honest placeholder attribution rather than a fabricated journalist.
11. **Caption and credit are optional and only render when present.** Every mock story has `imageUrl: undefined`, so every hero renders placeholder art. Printing `Photo: Andrew Harnik/Getty Images` under a gradient is a lie — but dropping it loses reference fidelity. So the fields are optional: the reference article carries the transcribed caption + credit (fidelity), the 11 derived articles omit both (honesty).
12. **`bias_label` is derived from the percentages per §19's own rule**, in `biasLabelFor(bias)`: the strongest percentage wins, unless the top two are within 5 points, in which case `mixed`. This keeps every label consistent with the bar next to it and makes the `33 / 34 / 33` climate story read `mixed` rather than a meaningless `center`.
13. **`Top Sources` rotates a shared pool.** A module-level `SOURCE_POOL` of 10 outlets with fixed leans, whose first 8 are the reference's 8 in the reference's order. Story *i* shows `pool[(i + n) % 10]` for `n = 0…7`, so story 0 renders the mockup exactly and no two articles show an identical list. Shared placeholder data, commented as such.
14. **Related items link only when their target exists.** The reference's 6 related titles are Iran-specific stubs that are not in `TOP_NEWS`, so the reference article's related cards are **inert** (`slug` omitted) with a `TODO`. The other 11 articles' related lists are built from real `TOP_NEWS` stories — same category first, then feed order, wrapping, self excluded — so those cards are real links. One component, one optional `slug` prop.
15. **`bias_score` and `model` are stored-not-displayed fields** (§19 lists them as persisted, and the reference shows neither), so they are omitted from the mock type. `sentiment_score` is kept because the `Framing Details` panel prints the label with its score.
16. **The headline is the page `<h1>`** at `text-h1`; `Related Stories`, `Bias Distribution`, and the panel titles are `<h2>`; related item titles are `<h3>`. The sidebar is **not sticky** — the reference gives no evidence for it and it is behaviour the task did not ask for.

## Implementation requirements

### `lib/mock/article-details.ts`

Shaped to the eventual `articles` + `article_analyses` join (AGENTS.md §7 / §19) so the Supabase swap is mechanical. Fields already on `TopNewsStory` (`title`, `category`, `country`, `imageUrl`, `bias`, `sourceCount`) are **not** duplicated.

```ts
export type SentimentLabel = "positive" | "neutral" | "negative";
export type BiasLabel = "left" | "center" | "right" | "mixed" | "unclear";
export type SourceLean = "left" | "center" | "right";

export type ArticleSource = { name: string; lean: SourceLean };

export type RelatedStory = {
  title: string;
  category: string;
  country: string;
  publishedAt: string;   // pre-formatted, e.g. "May 29, 2026"
  readingTime: string;   // e.g. "8 min read"
  /** Set only when the target exists in TOP_NEWS; otherwise the card is inert. */
  slug?: StoryId;
};

export type ArticleDetail = {
  author: string;
  publishedAt: string;
  readingTime: string;
  imageCaption?: string;        // only when a real photo exists (decision 11)
  imageCredit?: string;
  paragraphs: string[];         // articles.raw_text, split for rendering
  summary: string[];            // article_analyses.summary, as bullets
  summaryGeneratedAt: string;
  summaryReadingTime: string;
  sentimentLabel: SentimentLabel;
  sentimentScore: number;       // −1…1
  confidence: number;           // 0…1
  framingNotes: string;
  loadedTerms: string[];
  disclaimer: string;
  related: RelatedStory[];
};
```

Helpers, all pure and deterministic (no `Date.now()`, no randomness — the page is prerendered):

- `biasLabelFor(bias): BiasLabel` — decision 12.
